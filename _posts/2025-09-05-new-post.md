## Protocol stack
A **protocol stack** is a layered architecture where each layer provides services to the layer above it and uses services from the layer below it. Each layer handles a specific aspect of communication and abstracts away lower-level details.

There are two main academic models for protocol stacks:
1. **OSI Model**: A 7-layer model that includes:
   1. Physical (cables, radio waves)
   2. Data Link (Ethernet, WiFi)
   3. Network (IP routing)
   4. Transport (TCP, UDP)
   5. Session (connection management)
   6. Presentation (encryption, compression)
   7. Application (HTTP, FTP, etc.)

2. **TCP/IP Model**: A 4-layer model that includes:
   1. Network Access (Ethernet, WiFi)
   2. Internet (IP routing)
   3. Transport (TCP, UDP)
   4. Application (HTTP, FTP, etc.)

### REST and gRPC
These define how you structure and invoke remote operations:
- REST: Resource-oriented protocol using HTTP verbs (GET, POST, PUT, DELETE) where we manipulate resources via URLs
- gRPC: RPC-oriented protocol where we directly call remote functions/methods

## Serialization/Encoding layer

### JSON and Protocol Buffers
These define how data is encoded on the wire:
- JSON: Text-based, human-readable serialization format
- Protocol Buffers: Binary, schema-based serialization format

This layer determines:
- Message size and parsing speed
- Schema evolution capabilities
- Type safety and validation
- Cross-language compatibility

Usually we choose interaction model(REST vs gRPC) based on API design needs, and serialization format(JSON vs Protobuf) based on performance and compatibility needs. But we can mix and match them too.
These layers are largely independent - you can mix and match:
- REST + JSON: Most common web API pattern
- REST + Protobuf: Less common but possible (though we lose some of REST's human-readable benefits)
- gRPC + Protobuf: Standard gRPC approach
- gRPC + JSON: Possible with gRPC-Web or custom implementations
